Why Did It Come Back?

Paste a listing and its returns. Get one cause per SKU, the buyer's own words as proof, and a fix you can paste into the listing today. Built for a seller who reads returns alone, one ASIN at a time.

Build hour 1 of 1 Checkpoint 2 · 0:30 Scope widened: Owner Console, all four challenges

The problem, in the seller's words

the "reason" field customers pick at checkout is useless, everything's either "changed my mind" or "doesn't fit", neither tells me if it's the product, the photos, or the sizing.r/AmazonSeller, seller above 20% returns

Amazon charges a returns processing fee above the category threshold, and the "Frequently returned item" badge cuts conversion by 25 to 50%. The only fix the thread found was manual: read your own returns, work out why, rewrite the listing. Sizing tools that could help (True Fit, Bold Metrics) start around $1,650 a month and cannot be installed on a marketplace listing.

Enterprise layer

  • Multi-tenant API keys, per-tenant rate limits, append-only audit log with hashed inputs and the prompt version behind every answer
  • PII redaction before any model call; buyer text treated as untrusted input with an injection detector; output guard checks every quote against the inputs
  • Retention sweeps (audit 90d, imports 30d); Docker deploy; eval gates as release controls
  • Compliance mapped per module: GDPR/CCPA and Amazon's Data Protection Policy for returns; Google/Meta API policies and FTC substantiation for ads; CCTV signage, no biometrics, employee-safety rules for theft

How it is being built: a loop, not a prompt

1 · ConsoleMaster meta-prompt writes system prompt vN
2 · Agents7 agents build, synthesise cases, run
3 · Eval gate≥80% cause accuracy · 100% grounded · 100% low-data honesty
4 · FailuresBad cases go back into the meta-prompt → vN+1

No product prompt is written by hand. The failure report from each eval run is the only thing that changes the next version, so every improvement is traceable to a case that failed.
